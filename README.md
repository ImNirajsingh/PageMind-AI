# 📚 Comprehensive RAG System & Document Assistant

Welcome to the **Retrieval-Augmented Generation (RAG) System**. This repository serves as a complete toolkit for building, testing, and deploying LLM applications that can "read" and reason over your private documents. 

This project demonstrates various techniques in the LangChain ecosystem, including basic text chunking, advanced multi-query retrieval, Maximum Marginal Relevance (MMR) search, and a full-stack interactive web application built with Streamlit.

## 🧩 Core Modules & Code Explanations

Below is a detailed breakdown of the core files in this repository, explaining what the code does step-by-step.

### 1. The Main Web App (`app.py`)
This file powers the user interface. It allows users to upload a PDF, vectorize it, and ask questions.

* **Imports & Setup:**
  ```python
  import streamlit as st
  import tempfile
  from langchain_huggingface import HuggingFaceEmbeddings
Loads Streamlit for the UI, tempfile to handle PDF uploads securely in memory/disk, and the HuggingFace embedding model.

The Embedding Model:

Python
embeddings = HuggingFaceEmbeddings(model_name="sentence-transformers/all-MiniLM-L6-v2")
This initializes a local, lightweight embedding model that converts text into dense mathematical vectors (arrays of numbers) so the database can understand semantic meaning.

Document Processing & Database Creation:

Python
loader = PyPDFLoader(file_path)
docs = loader.load()
splitter = RecursiveCharacterTextSplitter(chunk_size=1000, chunk_overlap=200)
chunks = splitter.split_documents(docs)
Once the PDF is uploaded, PyPDFLoader extracts the raw text. Because LLMs have context limits, the RecursiveCharacterTextSplitter breaks the book into chunks of 1000 characters. The chunk_overlap=200 ensures that if a sentence is cut in half, the next chunk contains the previous 200 characters to maintain context.

The Retriever & LLM:

Python
retriever = vectorstore.as_retriever(search_type="mmr", search_kwargs={"k": 4, "fetch_k": 10, "lambda_mult": 0.5})
llm = ChatMistralAI(model="mistral-small-2506")
The retriever searches the chroma_db. It uses mmr (Maximum Marginal Relevance) to fetch 10 documents (fetch_k), and selects the top 4 (k) that are both highly relevant to the question and diverse from each other. It then initializes the Mistral AI model to generate the final response.

2. Advanced Retrievers (retrievers/)
Multi-Query Retrieval (multiquery.py)
Standard similarity search often fails if the user's wording doesn't match the document's wording.

The Code:

Python
multi_query_retriever = MultiQueryRetriever.from_llm(retriever=retriever, llm=llm)
docs = multi_query_retriever.invoke("What is gradient descent?")
How it Works: Instead of passing the user's exact question to the database, this module passes the question to the LLM first. The LLM generates 3 to 5 different variations of the question. The system searches the database for all variations, takes the union of the results, and returns a much richer set of documents.

MMR vs Similarity (mmr.py)
The Code:

Python
similarity_retriever = vectorstore.as_retriever(search_type="similarity", search_kwargs={"k":3})
mmr_retriever = vectorstore.as_retriever(search_type="mmr", search_kwargs={"k":3})
How it Works:

similarity search strictly looks for chunks with the closest vector distance. This can result in pulling 3 chunks that say the exact same thing.

mmr search balances relevance and diversity. It finds the most relevant chunk, and then penalizes other chunks that are too similar to the first one, ensuring the LLM gets a broader context.

3. Document Ingestion (document loaders/)
Web Scraping (pages.py)
The Code:

Python
from langchain_community.document_loaders import WebBaseLoader
docs = data.load()
How it Works: This directly scrapes the HTML from a provided URL, cleans it into raw text, and stores it as a LangChain Document object ready to be chunked and vectorized.

PDF Loading & Chunking (pdf.py)
The Code:

Python
text_splitter = RecursiveCharacterTextSplitter(chunk_size=100, chunk_overlap=20, length_function=len)
How it Works: This script specifically tests aggressive chunking on GRU.pdf. By setting the chunk size to 100, it creates very tiny segments. length_function=len tells the splitter to count by characters rather than tokens.

4. Vector Store Generation (Vector Store/DB.py)
The Code:

Python
embedding_model = GoogleGenerativeAIEmbeddings(model="models/gemini-embedding-001")
vectorstore = Chroma.from_documents(documents=docs, embedding=embedding_model, persist_directory="chroma-db")
How it Works: Instead of HuggingFace, this script leverages Google's Gemini embeddings API. It takes hardcoded Document objects containing facts about Python, Pandas, and Neural Networks, assigns metadata to them (e.g., {"source":"AI_book"}), and saves the resulting database to the local chroma-db folder.

⚠️ Troubleshooting & Common Errors
Error: ModuleNotFoundError: No module named 'torchvision'
You may encounter a missing torchvision dependency when the HuggingFace sentence-transformers library attempts to load its weights.

The Fix: You need to install PyTorch and its associated vision libraries explicitly. Run the following command in your activated .venv:

Bash
pip install torch torchvision torchaudio
(Note: If you are using a GPU, you may need to visit the official PyTorch website to get the specific installation command for your CUDA version).

Error: SQLite3 Version Compatibility with ChromaDB
ChromaDB requires SQLite version > 3.35.0. If you are on an older OS or using a specific Python build, Chroma might crash.

The Fix: Install pysqlite3-binary and add the following lines to the very top of app.py before importing Chroma:

Python
__import__('pysqlite3')
import sys
sys.modules['sqlite3'] = sys.modules.pop('pysqlite3')
